salvo

npm publish'ten önce, yayınlanacak paketin gerçekten söylediği şey olduğunu doğrular. Bir kez çalışır, sorun varsa sıfırdan farklı çıkar.

npx salvo

Neden yazıldı

bukalemun@1.5.0 npm'e 14:28'de çıktı. Çalışma zamanının sürümünü sabit koddan kurtaran commit 14:46'da girdi. Yayınlanan pakette bk.version hâlâ 1.3.2 diyordu — yani 1.5.0, düzelttiğini iddia ettiği hatayı taşıyarak yayınlandı.

Testler yeşildi; testler çalışma ağacına bakıyordu, tarball'ın içine kimse bakmamıştı. prepublishOnly da kurtarmadı: derliyordu ama sonucu commit'li dist/ ile karşılaştıran bir şey yoktu.

Aynı iki commit üzerinde

$ salvo bukalemun@f058fce        # npm'e kırık giden hâl
✗ version-echo  dist/bukalemun.cjs içinde sürüm "1.3.2" yazıyor, package.json "1.5.0" diyor.
✗ version-echo  dist/bukalemun.esm.js içinde sürüm "1.3.2" yazıyor…
✗ version-echo  dist/bukalemun.min.js  …
  6 engel, 1 uyarı — yayınlama.                       → çıkış 1

$ salvo bukalemun@decfe18        # düzeltilmiş hâl
  temiz — paket söylediği şey.                        → çıkış 0

Kontroller

KontrolYakaladığı
build-driftCommit'li çıktı, HEAD'in temiz bir kopyasından yapılan derlemeyle ayrışmış
version-echoPakete giren dosyalardaki sürüm bildirimleri package.json ile uyuşmuyor
git-stateYayınlanan ağaç commit'lenmemiş ya da pushlanmamış
entrypointsmain/module/types/exports/bin var olmayan dosyayı gösteriyor
secretsTarball'a .env, .npmrc, özel anahtar ya da token girmiş
tag-matchSürümle git etiketi ayrışmış; yayının kaynağı sonradan bulunamaz

CI'da

- uses: actions/checkout@v4
  with: { fetch-depth: 0 }     # build-drift `git archive HEAD` çalıştırır
- run: npx salvo
